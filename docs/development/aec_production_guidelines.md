# Material Insight AI Studio: AEC Production Guidelines

This document outlines the architectural and engineering guidelines for the evolution of the AI Studio into a High-Standardized Design Production Engine. All developers contributing to the multi-agent system and generation logic must adhere to these standards.

## 1. Operating Logic: Constrained Generative Design
The AI Studio is transitioning from "free-form chat" to **Constrained Generative Design**. 
*   **Rule:** No design artifact (blueprint, BOQ, or 3D model) should be generated without first being validated against the `src/lib/aec/compliance_rules.json`.
*   **Workflow:** User Request → Agent Orchestration → **Compliance Validation** → Artifact Generation.

## 2. Professional Role Hierarchy (The "Hive" Model)
The backend orchestration must mimic the professional boundaries defined by the Nigerian National Building Code:
*   **Architectural Lead:** Handles spatial layout, setbacks (Lagos: 6m front, 3m sides), and room functionality.
*   **Structural Engineer:** Validates load-bearing elements (Residential: 2.0kN/m2 live load) and beam spans (Max 4.5m for standard residential).
*   **Quantity Surveyor:** Calculates material volumes using provided constants (e.g., 10 blocks/m2 for 9-inch walls).
*   **Professional Builder:** Responsible for the **Buildability Analysis** and safety protocols (Hoarding > 2.4m if near street).

## 3. Mandatory Documentation Outputs
Every "Verified Project" package generated by the AI Studio must contain the following documents:
1.  **Contract Drawings & Specs:** (Architectural/Engineering).
2.  **Priced BOQ:** (Quantity Surveying).
3.  **Project Quality Management Plan (QMP).**
4.  **Health & Safety (H&S) Plan.**
5.  **Construction Programme:** (Implementation schedule).
6.  **Buildability/Maintainability Report.**

## 4. Technical Constraints (Source of Truth)
Always reference `src/lib/aec/compliance_rules.json` for:
*   **Minimum Room Sizes:** (e.g., Bedrooms must be ≥ 9.0m2).
*   **Mix Ratios:** (C20: 1:2:4; C25: 1:1.5:3).
*   **Structural Ratios:** (Span-to-depth ratio of 15 for simply supported beams).

## 5. Development Strategy: Surgical & Modular
*   All changes must be surgical, preserving existing non-AEC logic.
*   Changes must be staged, committed, and pushed modularly (one feature per push).
